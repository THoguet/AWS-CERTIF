## Buckets and objects

- A **bucket** lives in one Region and has a **globally unique** name (3–63 chars, lowercase, DNS compatible).
- An **object** = key (the full "path", e.g. `reports/2026/q3.pdf`) + data (0 B to **5 TB**) +
  metadata + optional tags. "Folders" are just key prefixes.
- **System metadata** (`Content-Type`, `Content-Length`, `ETag`, `Last-Modified`...) and **user
  metadata** (`x-amz-meta-*`, set at upload, ~2 KB). Changing metadata requires copying the object onto itself.
- **Object tags** (up to 10 key/value pairs) can be changed in place. They drive lifecycle rules,
  IAM conditions and cost allocation.
- **Consistency**: S3 has offered **strong read-after-write consistency** for all PUTs, DELETEs and
  LIST operations since December 2020. A read right after a write sees the new data.

```python
s3.create_bucket(Bucket="reports-paris", CreateBucketConfiguration={"LocationConstraint": "eu-west-3"})
s3.put_object(Bucket="reports-paris", Key="2026/q3.pdf", Body=data,
              ContentType="application/pdf", Metadata={"owner": "finance"})
s3.head_object(Bucket="reports-paris", Key="2026/q3.pdf")   # metadata only, no download
```

> **Trap** — `CreateBucket` outside **us-east-1** needs a `LocationConstraint`. In us-east-1 you
> must not send one. Otherwise you get `IllegalLocationConstraintException` (exercise `s3_1`).

## Uploads, downloads and performance

| Technique | When |
|---|---|
| **Single PUT** | Up to **5 GB** per request |
| **Multipart upload** | Recommended above ~**100 MB**, **required above 5 GB**. Parts of 5 MB–5 GB (the last can be smaller), up to 10,000 parts. Parts upload in parallel and retry individually |
| **Byte-range GET** (`Range` header) | Download parts of an object in parallel, or read just the header of a file |
| **S3 Transfer Acceleration** | Faster long-distance uploads through CloudFront edge locations (`bucket.s3-accelerate.amazonaws.com`), extra cost |
| **CloudFront in front of S3** | Caching for reads close to users (chapter 8) |

- Request-rate guidance: at least **3,500 PUT/COPY/POST/DELETE** and **5,500 GET/HEAD requests per
  second per prefix**, and you can use many prefixes. S3 scales automatically, but sudden extreme
  spikes can produce `503 SlowDown`, which you retry with backoff.
- Incomplete multipart uploads keep their parts **stored and billed** until you complete or abort
  them. Add a lifecycle rule `AbortIncompleteMultipartUpload`.
- With **SSE-KMS**, each upload/download calls KMS, which has its own request quotas. Use **S3 Bucket Keys** to cut KMS calls.
- boto3's managed transfers (`upload_file`, `download_file` + `TransferConfig`) handle multipart and parallelism for you.
- **S3 Select** (SQL on one object) is no longer offered to new customers. For SQL over S3 data, use **Athena**.

## Access control

S3 access is decided by IAM identity policies, **bucket policies**, ACLs (legacy), Block Public
Access, and KMS key policies for SSE-KMS objects.

- **Block Public Access** (account and bucket level) overrides any policy or ACL that would make data public. It is on by default for new buckets.
- **Object Ownership = Bucket owner enforced** (the default since 2023) **disables ACLs**. Use policies only.
- **Bucket policies** are resource-based: cross-account access, enforcing TLS
  (`aws:SecureTransport`), enforcing encryption headers, restricting to a VPC endpoint
  (`aws:SourceVpce`), or granting CloudFront access (Origin Access Control).

```json
{"Sid": "DenyInsecureTransport", "Effect": "Deny", "Principal": "*", "Action": "s3:*",
 "Resource": ["arn:aws:s3:::payroll", "arn:aws:s3:::payroll/*"],
 "Condition": {"Bool": {"aws:SecureTransport": "false"}}}
```

### Presigned URLs

A presigned URL lets anyone holding it perform **one operation** (GET or PUT of one object, or a
form POST) until it expires, **with the permissions of the signer**:

```python
url = s3.generate_presigned_url("get_object", Params={"Bucket": b, "Key": k}, ExpiresIn=300)
form = s3.generate_presigned_post(b, "avatars/u-7.png",
                                  Fields={"Content-Type": "image/png"},
                                  Conditions=[["content-length-range", 0, 2 * 1024 * 1024],
                                              {"Content-Type": "image/png"}],
                                  ExpiresIn=600)
```

- Maximum validity: **7 days** with IAM user credentials (SigV4). URLs signed with **temporary
  credentials** (a role, e.g. from Lambda) stop working when those credentials expire, possibly earlier than `ExpiresIn`.
- Use it for direct browser/mobile uploads and downloads of private objects without proxying the
  bytes through your backend.

> **Exam tip** — "Let users download private files for a limited time without AWS credentials" →
> **presigned URL** (or CloudFront signed URLs/cookies when content is served through CloudFront).

### CORS

A browser app on `https://app.example.com` that calls the bucket's endpoint is making a
cross-origin request. The browser sends a **preflight** `OPTIONS` request and blocks the call
unless the bucket returns the right CORS headers:

```json
[{"AllowedOrigins": ["https://app.example.com"], "AllowedMethods": ["GET", "PUT"],
  "AllowedHeaders": ["*"], "ExposeHeaders": ["ETag"], "MaxAgeSeconds": 3000}]
```

> **Trap** — A CORS error is enforced **by the browser**. The fix is a CORS configuration on the
> **target** (the bucket, or the API), not an IAM permission.

## Encryption

| Option | Keys managed by | Notes |
|---|---|---|
| **SSE-S3** | S3 (AES-256) | **Default for all new objects since Jan 2023**. Header `x-amz-server-side-encryption: AES256` |
| **SSE-KMS** | AWS KMS (AWS managed key `aws/s3` or a **customer managed key**) | Key policy control, CloudTrail audit of key use, key disable/rotation. Header `aws:kms` + `x-amz-server-side-encryption-aws-kms-key-id`. KMS quotas apply, so use **Bucket Keys** |
| **DSSE-KMS** | KMS, two layers of encryption | Compliance requirements for dual-layer encryption |
| **SSE-C** | **You** provide the key with every request (over HTTPS) | S3 never stores the key. Lose it and you lose the data |
| **Client-side** | You (e.g. with KMS data keys, AWS Encryption SDK) | Data is encrypted before leaving your app (chapter 13) |

- **Default bucket encryption** applies when the request has no encryption header. To **force**
  SSE-KMS, use a bucket policy that denies `PutObject` without
  `s3:x-amz-server-side-encryption = aws:kms` (exercise `iam_4`), or set SSE-KMS as default encryption.
- Encryption **in transit**: HTTPS endpoints. Enforce with `aws:SecureTransport`.
- Reading an SSE-KMS object requires `kms:Decrypt` on the key, and writing requires `kms:GenerateDataKey`.

## Storage classes

| Class | Use | Notes |
|---|---|---|
| **S3 Standard** | Frequently accessed data | ≥ 3 AZs, millisecond access |
| **S3 Intelligent-Tiering** | Unknown or changing access patterns | Moves objects between tiers automatically. Small monitoring fee per object, no retrieval fee |
| **S3 Standard-IA** | Infrequent access, but immediate when needed | Retrieval fee per GB, minimum 30-day storage charge, 128 KB minimum billable size |
| **S3 One Zone-IA** | Re-creatable, infrequent data | A single AZ, cheaper |
| **S3 Glacier Instant Retrieval** | Archives read about once a quarter, needing milliseconds | 90-day minimum |
| **S3 Glacier Flexible Retrieval** | Archives. Restore in minutes to hours (Expedited 1–5 min, Standard 3–5 h, Bulk 5–12 h) | 90-day minimum |
| **S3 Glacier Deep Archive** | Long-term retention (7–10 years) | Cheapest. Standard restore within 12 h, Bulk within 48 h. 180-day minimum |

> **Exam tip** — "Data accessed rarely but must be available **immediately**" → Standard-IA (or
> Glacier Instant Retrieval for very rare access). "**Unknown/unpredictable** access patterns" → Intelligent-Tiering.

## Lifecycle, versioning and replication

**Lifecycle rules** (per prefix or tag) automate *transitions* between classes and *expiration*:

```json
{"ID": "logs-retention", "Status": "Enabled", "Filter": {"Prefix": "logs/"},
 "Transitions": [{"Days": 30, "StorageClass": "STANDARD_IA"}, {"Days": 90, "StorageClass": "GLACIER"}],
 "Expiration": {"Days": 365},
 "NoncurrentVersionExpiration": {"NoncurrentDays": 30},
 "AbortIncompleteMultipartUpload": {"DaysAfterInitiation": 7}}
```

- Objects must stay **30 days** in Standard before moving to Standard-IA or One Zone-IA.
- **Versioning** keeps every version of an object. A DELETE without a version id adds a
  **delete marker**, so the object can be restored. Once enabled, versioning can only be *suspended*, not removed.
  Combine with **MFA Delete** and **Object Lock** (WORM: governance/compliance modes, legal hold) for strong protection.
- **Replication**: **CRR** (cross-Region) or **SRR** (same-Region). Requires versioning on **both**
  buckets and an IAM role. Only **new** objects are replicated (use **S3 Batch Replication** for existing ones).
  Delete markers are not replicated by default.

## Event notifications

S3 can emit events (`s3:ObjectCreated:*`, `s3:ObjectRemoved:*`, `s3:ObjectRestore:*`,
`s3:Replication:*`...) filtered by **prefix and suffix**, to:

- **SNS**, **SQS** (standard queues; not FIFO as a direct destination), **Lambda**,
- or **EventBridge** (enable it on the bucket): every event, advanced filtering with event
  patterns, multiple targets, archive and replay.

```text
S3 ──ObjectCreated (prefix uploads/, suffix .jpg)──► SQS ──► Lambda (thumbnailer)
```

- The destination's **resource policy** must allow S3 to publish (`aws:SourceArn` = the bucket ARN).
- Delivery is typically within seconds, **at least once**. Make consumers idempotent.
- Keys in the event are **URL-encoded** (`my+photo.jpg`), so decode them (`unquote_plus`).
- Writing output to the **same bucket and prefix** that triggers the function creates an
  **infinite loop**. Use another bucket or a filtered prefix (exercise `s3_7`).

> **Exam tip** — Several consumers for the same S3 event? A prefix/suffix combination can only
> target one destination per event type, so fan out with **SNS → SQS queues** or use **EventBridge**.

## Static website hosting

A bucket can serve a static site over HTTP (`index.html`, `error.html`) at the website endpoint
`http://bucket.s3-website.<region>.amazonaws.com`. That requires public read access. Production
setup: **CloudFront + Origin Access Control (OAC)** with a private bucket, HTTPS via ACM, and a
custom domain via Route 53.

## Summary

- Strong read-after-write consistency. 5 TB max object, 5 GB max single PUT, multipart above ~100 MB.
- Presigned URLs give temporary access with the signer's permissions. CORS is a browser rule configured on the bucket.
- SSE-S3 by default. SSE-KMS for key control and audit (watch KMS quotas, use Bucket Keys). SSE-C = your key in every request.
- Lifecycle rules move and expire data (30-day minimum before IA). Versioning protects against deletes. CRR/SRR need versioning.
- Event notifications go to SNS/SQS/Lambda/EventBridge, at least once, with URL-encoded keys. Beware of recursive triggers.
